Native revisions are opaque equality tokens, NOT backend file versions or a claim of globally ordered edit numbers. Word also increments its layout revision for some non-content work and `touch` wraps; conservative extra notifications/saves are preferable to missed edits. Do not use undo depth, boolean dirty, JS frame count or pointer address as the edit revision. UI text still in a native composition/editor is committed or explicitly rejected as busy by the serializer before taking its revision; an in-progress IME must never be silently discarded.

## Proposed protocol 2 messages

All messages use exact same-origin parent/source validation, `protocol:2`, the exact new artifact `version`, and `${app}:…` type names. Legacy protocol/assets remain separate, without inferred capabilities.

- `ready`: capabilities `{serialize:true,parsedOpen:true,documentRevision:true,durableSaveAck:true,theme:true}` only after all native hooks actually connect. It means the bridge is listening, NOT that a document is parsed/painted.
- `open`: existing bounded document bytes/name and explicit format/write policy, plus `openId`.
- `opened`: `{openId,documentId,revision}` only after successful native parsing and insertion into the intended session. Password-required/unsupported/corrupt inputs report an explicit result instead; native parser success does not assert all layout/font/render work has finished. A separate first-painted signal can be added only at the actual UI pass.
- `dirty`: `{openId,documentId,revision,dirty}` on every native signature change, including another edit while `dirty:true`. Report the observed current native identity after each logic/UI mutation boundary, not merely boolean transitions. Host cannot receive intermediates that occur entirely between observations, but the latest revision must be reported and cannot be mistaken for the acknowledged snapshot.
- `request-save`: `{requestId,openId,documentId,saveAs?,name?}`. Default is `saveAs:false`, existing-native replacement only. `saveAs:true` requires an explicit user-chosen copy name and authorized output extension; autosave never chooses a destination or silently creates repeated PPTX copies. Reject wrong document/open identity or read-only replacement before queuing native work. The native owner commits or refuses pending native editing, THEN captures the revision and serializes. No focus changes, key events or invented bytes.
- `save`: `{requestId,openId,documentId,revision,saveId,name,saveAs,bytes}`. This revision is the immutable serialized snapshot. One snapshot is in flight at a time; retain its exact bytes and identity through post failure/conflict/failed persistence. Repeating its request while pending resends those same bytes, not newer edits. A new request while pending gets `busy`, never overwrites recovery data. Keep explicit copy/export separate from automatic replacement.
- `save-result`: echoes `{requestId,saveId,openId,documentId,revision}` plus durable saved/failure status. Positive acknowledgements use **`fileRevision`** for the backend file version; envelope `revision` always means the native opaque snapshot token, unlike protocol1. Do not overload it.
- `saved`: echoes snapshot tuple plus `{dirty,currentRevision}` AFTER the native owner consumes the durable ack. Clean only when the current native document and revision are still the captured ones. Otherwise keep newer work dirty and schedule another save. A callback returning after a document switch must never clean the newly active file.
- `set-theme`: `{requestId,theme:"light"|"dark"|"system"}`; `theme-applied`: `{requestId,theme,resolvedTheme}` after the actual native UI pass applies the requested palette. Apply DESIGN to UI chrome/tokens, never to document typography, slide theme, spreadsheet cell styles, PDF page colors or stored content. No CSS inversion/filter. Parent Light/Dark overrides OS; System follows changes without reload. Accessibility/focus/selection contrast remain native theme obligations.

### Approved manual/error/detachment policy

Native Ctrl+S/File Save emits `save-requested` as intent; the SDK performs its immediate manual flush through `request-save`. The native serializer is a direct internal method, never the intercepted File Save command (no request loop or uncorrelated clean path). Stable local error codes are `busy`, `identity-changed`, and `serialization-failed`; consumers do not parse human text. Native FileNew/Open identity changes detach the host source and disable replacement/autosave until explicit copy/reopen; do not silently rebind the old file.

SaveCopy is not a save to the original source: a durable copy does not retarget native source paths or clear the original source's dirty baseline. SDK must not adopt its `fileRevision` as the original source's version. All wire schemas/types will come from the parent-owned public SDK `./editor-runtime` export; this note is a handoff, not a parallel implementation authority.

### PDF acknowledgement hazard

`Session::mark_saved` rebuilds the live `editor.cos` from the saved bytes (`engine/src/session/save.rs:66-91`). Calling it after a newer edit would replace that newer edit with the older snapshot. The initial safe bridge must call it ONLY for exact current document+generation; otherwise retain current native state/dirty and request a fresh serialization after acknowledging the durable older snapshot. No optimistic rebasing by copying an old save over the current editor.

### Source patch contract

Patch generators accept independently pinned source maps and authored bridge/theme inputs, reject an unexpected anchor/version, return the complete final-vs-original source delta, and never write into a retained source/build/runtime directory. Adapters expose four narrow operations to their native frame owner: take command; report parsed-open/identity; report actual serialized bytes+captured identity; consume ack with same-identity guard. New theme work is applied inside the UI pass. No new Rust dependency or lockfile drift without explicit review.

Before source freeze: test repeat edit while dirty, commit-pending-input, edit during pending save then delayed ack, document switch then ack, read-only/copy policy, post failure replay, conflict recovery, malformed/wrong-origin/wrong-parent/wrong-version messages, and actual Light/Dark/System chrome. A protocol unit fixture alone is not proof that the WASM adapter is connected.
